01｜项目为什么“推着推着就散了”

项目失控不一定是执行力单点问题，更常见的是计划、过程、复盘三个断点叠加。

1计划不清

目标像口号：范围、交付物、负责人、节点不清，导致“都在做、没人负责”。

2过程失控

会议只汇报进度，不暴露风险；问题没有升级机制，延误到节点才被发现。

3结果无复盘

项目完成后没有标准化、横展和经验沉淀，下个项目继续从零摸索。

4三件工具各司其职

PDCA负责闭环，甘特图负责节奏，里程碑负责验收；三者组合后，项目管理才从“催进度”升级为“控交付”。

讲师话术｜项目管理的第一步不是催人，而是把任务、节点、风险、验收条件晒在一张图上。

02｜PDCA：项目闭环的管理发动机

PDCA不是四个英文单词，而是项目从定义到固化的最小管理闭环。

P｜Plan 计划定义目标、范围、WBS、风险、资源、验收标准。
D｜Do 执行按计划推进，日清问题，异常升级，保留证据。
C｜Check 检查对照里程碑评审：进度、质量、成本、风险。
A｜Act 处置固化标准、复盘经验、横展复制、关闭项目。
讲师话术｜PDCA的价值在“每一轮都有证据”，没有证据的项目推进，最后只能靠口头解释。

03｜Plan：把愿望拆成可执行结构

计划阶段的核心不是写漂亮方案，而是把目标、边界、任务、资源、风险一次性讲清楚。

5W2H定义项目边界

What 交付什么｜Why 为什么做｜Where 在哪应用｜When 何时完成｜Who 谁负责｜How do 怎么做｜How much 资源/成本。

WBS拆任务颗粒度

一级：项目阶段；二级：工作包；三级：可执行任务；四级：责任与验收。任何“跟进、协调、推进”都不是合格任务，必须拆成可交付物。

Plan输出物：项目章程｜WBS任务清单｜风险清单｜资源需求｜里程碑验收标准。
讲师话术｜计划不是越细越好，而是细到责任人可以马上行动、评审人可以明确验收。

04｜甘特图：把WBS任务放到时间轴上

甘特图不是“漂亮进度表”，而是项目节奏、前后依赖、关键路径与里程碑的可视化。

任务 / 阶段W1W2W3W4W5W6W7W8
项目启动 / 需求澄清
现状数据收集 / 测时
方案设计 / 评审冻结
样机 / 线体 / 系统实施
试运行 / 问题闭环
验收 / 标准化横展
判读要点：条形＝任务持续时间；菱形＝里程碑；空白＝缓冲/等待；重叠＝并行；前后衔接＝依赖。
讲师话术｜甘特图要一眼看出：当前在哪一周、卡在哪个任务、哪个里程碑要被保护。

05｜Do：用日清节奏防止项目失速

执行阶段不怕暴露问题，怕的是问题已经发生却还在甘特图上显示“正常”。

任务日清

当日任务必须有状态：未开始 / 进行中 / 完成 / 阻塞。

异常升级

超过24小时未解决的问题进入升级机制，不让问题沉底。

证据留痕

照片、数据、会议纪要、验收记录形成可追溯项目档案。

会议节奏

10分钟站会 + 1张问题清单 + 1张甘特图版本更新。

现场话术｜今天只问三件事——已完成什么、卡住什么、需要谁支持。

06｜Check：里程碑评审是“能不能过关”

里程碑必须提前定义验收条件，否则项目评审会变成主观争论。

里程碑进度质量 / 技术成本 / 资源风险
M1 立项目标/范围确认技术路径初判预算/资源明确主要风险识别
M2 方案冻结计划基线确认方案评审通过采购/人力锁定高风险有预案
M3 试运行按期进入现场数据达到阈值成本偏差可控异常闭环率≥90%
M4 验收交付物齐套KPI达成收益核算通过遗留项有Owner
红灯｜必须升级不满足关键验收条件，必须升级或调整基线。
黄灯｜限时纠偏存在偏差但有补救方案，限定时间纠偏。
绿灯｜阶段放行条件达成，可进入下一阶段。
讲师话术｜里程碑评审的标准句式：证据是否充分？偏差是否可控？是否允许进入下一阶段？

07｜Act：把一次改善变成组织能力

项目不是“做完就完”，而是把一次改善沉淀为标准、收益、经验和可复制能力。

固化标准

SOP / 点检表 / 参数表 / 培训资料。

收益复盘

效率、成本、质量、交付、库存等改善收益。

经验沉淀

问题库、风险库、最佳实践、踩坑记录。

横展复制

向相似产品线、相似工序、相似业务场景扩散。

关闭项目四个条件：交付物齐套｜KPI达成或偏差批准｜遗留问题有Owner与期限｜标准文件已发布并培训。
讲师话术｜项目关闭不是“大家辛苦了”，而是确认成果、文件、问题、经验都已经落地。

08｜PDCA × 甘特图：一套推进控制逻辑

用PDCA做闭环，用甘特图控节奏，用里程碑做阶段放行。

P｜立项/计划目标、WBS、风险、基线。
D｜实施推进任务日清、异常升级。
C｜里程碑评审证据、偏差、放行。
A｜标准化复盘文件、收益、横展。

计划基线

未经批准不随意改范围、改节点。

版本管理

甘特图每次更新保留版本号和原因。

风险前置

风险不等于问题；问题已发生，风险要提前防。

收益核算

效率 / 质量 / 成本 / 交付改善必须量化。

讲师话术｜项目推进不是把计划改到看起来正常，而是让事实、偏差、决策在同一张图上对齐。

09｜话术场景：单件流标杆线体推进

把争论拉回事实，把责任拉回任务，把进度拉回里程碑。

项目目标

将装配线打造为单件流标杆线体，降低等待与在制，提升节拍稳定性与现场可视化。

PDCA对应动作

P：现状测时 / 瓶颈识别；D：线体布局 / 工位重排；C：节拍验证 / 异常闭环；A：标准产能 / 培训横展。

现场主持话术今天我们不争论谁忙谁不忙，只看三个事实：①当前瓶颈工位在哪；②本周里程碑能否过关；③需要谁在什么时间前解决什么问题。

10｜三类会议话术

项目经理的价值，不是替别人做事，而是让事实、责任、风险、决策持续透明。

启动会本项目今天先冻结三件事：目标、边界、里程碑。没有边界的项目，后续一定会被无限加需求。
周例会请每位Owner只讲事实：上周完成什么，本周完成什么，卡点是什么，需要谁决策。
评审会我们只按验收条件判定：证据充分就放行；证据不足就限期补证；关键偏差必须升级决策。
高质量提问这个动作能否直接支持项目KPI？这个任务的Owner是谁？最晚何时提交什么结果？如果本周不解决，会影响哪个里程碑？用什么数据或现场证据证明已经完成？

11｜OPL落地模板：一页带走

任选一个真实项目，24小时内完成项目PDCA闭环表与里程碑甘特图初版。

P 计划

目标/KPI、WBS、风险、资源、里程碑。

D 执行

任务清单、日清机制、异常升级、证据留痕。

C 检查

进度、质量、成本、风险、验收条件。

A 处置

标准化、复盘、收益核算、横展复制。

结课金句

没有PDCA，项目容易失去闭环；没有甘特图，项目容易失去节奏；没有里程碑，项目容易失去验收标准。

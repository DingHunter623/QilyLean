# QilyLean 双站同步策略

状态：长期执行基线

## 一、总原则

`qilylean.com` 是全球主站与完整品牌/知识资产主源；`qilylean.cn` 是中国大陆站，当前处于预生产阶段，未来面向国内业务转化、主体合规与本地高速访问。

双站不做 100% 镜像复制，采用：

> **COM 主源维护 → 变更分级 → CN 选择性影子同步 → 独立验收 → 独立发布**

任何 `.com` 运维都先保证全球主站自身正确，再判断是否对 `.cn` 有价值；不因同步而破坏 `.com` 既有 SEO、视觉、速度和交互。

## 二、A 类：默认同步

以下变更默认同步到 `.cn`，但允许针对中国站做本地化实现：

1. QilyLean VI 主色、字体层级、间距、卡片、按钮、导航、页脚等视觉基线；
2. 可视化缺陷修复：错位、溢出、字号、对齐、响应式、首屏抖动、旧版闪现；
3. 交互与可用性修复：导航、锚点、返回顶部、分享、键盘可访问性、触控区域；
4. 性能优化：静态资源、缓存、压缩、预加载/预取策略、图片体积与加载策略；
5. 安全与运维：安全头、404/50x、回滚、发布 Guard、CI/Poka-yoke；
6. 六大业务的一级定位、核心术语、方法论框架和品牌主张发生实质性变化；
7. 影响品牌一致性的重大文案、Logo、命名、联系方式或入口策略。

## 三、B 类：条件同步

以下内容不机械复制，由运维时判断是否适合中国站：

1. 首页模块新增/重排；
2. 项目案例、知识文章、精选简报；
3. SEO 文案、结构化数据、OG/Twitter 社交卡片；
4. 翻译器、海外平台入口、第三方工具；
5. 图片、视频、外链与大体积媒体；
6. 新工具、新 APP、新游戏下载页；
7. 市场推广、招聘、阶段性活动和短期专题。

判断标准：是否有助于国内访客理解、信任、转化，并且不会引入海外依赖、合规冲突或明显性能负担。

## 四、C 类：禁止直接同步

以下内容必须保持双站独立：

1. `canonical`、robots、sitemap、搜索引擎验证与站长平台配置；
2. ICP、公安备案、企业主体、统一社会信用代码、注册地址、合同/发票主体等法定信息；
3. 域名、证书、DNS、服务器、公网端口和环境变量；
4. `.com` 专属的全球站 SEO 权重策略；
5. 依赖海外 CDN / 海外脚本才能正常首屏渲染的资源；
6. 任何会导致 `.cn` 在备案/上线 Gate 未通过前解除 `noindex` 或开放公网的变更。

## 五、当前预生产阶段的同步节奏

在 `.cn` 尚未完成备案并正式上线前：

- 不追求与 `.com` 每次小改动实时同频；
- A 类重大修复/能力升级及时同步；
- B 类内容按阶段批量吸收；
- `.cn` 始终保留独立轻量化实现，优先本地资源和高速首屏；
- 所有同步后继续执行 `noindex,nofollow` + `robots.txt Disallow: /`；
- 不开放正式公网 80/443。

## 六、正式上线后的运行模式

备案和上线 Gate 全部通过后，双站采用：

1. `.com` 继续作为全球权威主源；
2. A 类变更随主站版本进行影子同步；
3. B 类内容进入中国站选编队列，不做全文机械镜像；
4. `.cn` 独立做百度、微信环境、国内网络性能与本地合规适配；
5. 两站相互提供明确入口，但避免 SEO 自我竞争和重复内容冲突。

## 七、运维执行口径

后续每次 QilyLean 官网运维，默认执行以下判断：

> **先修 `.com` → 判断 A/B/C 类 → 需要则同步 `.cn` → 分别跑回归与部署。**

若用户只提出 `.com` 的单点修复，但该问题属于 A 类，则视为已授权同步修复 `.cn`；若属于 B 类，按中国站价值判断；若属于 C 类，保持双站独立。

## 八、不可回归红线

- `.com` 任何同步动作不得降低现有可视化、速度、SEO 或交互；
- `.cn` 不得变成 `.com` 的未经筛选镜像；
- 中国站优先使用本地静态资源，避免海外链路成为首屏单点依赖；
- 未备案阶段禁止解除搜索引擎阻断或正式公网开放；
- 双站所有发布继续执行视觉、性能、功能、移动端与微信环境回归。

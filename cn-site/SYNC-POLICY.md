# QilyLean 双站同步策略

## 2026-10-18 公开内容与视觉同步合同

国际站是非商业正文、模块层级、版式及媒体的唯一源；中国站完整同步其公开工程事实、精选简报、项目图片/视频、现场照片与学习内容。不得以脱离上下文的“合同”等单个词删去技术概念、方法说明或历史工程事实。经营性页面、商业主体/签约付款模块、报价预约/获客表单和商业导流 CTA 按明确路由与模块排除。

中国站导航保留国际站九项非商业栏目，并保留“联系我们”至原 `/about/#contact`；联系方式内容、复制/拨号行为、国内翻译器及两项备案保持。精选简报隶属知识资产；行走印记隶属信任中心。

末级 `materialize-source-content-parity.py` 负责复制原正文结构和限定于正文的源 CSS；`source-content-parity.json` 逐页记录正文摘要和原始媒体路径，由本地与生产校验器核验。源项目公开视频、图片不以替代示意图冒充。生成与发布不得回退为旧七项导航，也不得覆盖已闭环的翻译服务或凭证。

以下历史规则以本节和当前用户授权为准；禁止商业导流不等于删除公开工程事实或中国站原有联系方式。

## 一、总原则

`qilylean.com` 是全球主站与完整品牌/知识资产主源；`qilylean.cn` 是中国大陆个人知识站。

双站采用“**全内容资产覆盖 + 中国个人站合规过滤**”模式：

> **COM 主源维护 → 全量识别公开内容资产 → 内容合规筛选 → CN 同步/个人知识化改写 → 独立验收 → 独立发布**

中国站长期目标不是维持少量精选页面，而是尽可能完整承接国际站已经公开的制造知识、精选简报、方法、工具说明、历史实践、学习资料与公开素材；凡属于个人知识分享边界的公开内容，应建立中国站对应页面，不再只以国际站外链替代。

“全套内容克隆”不等于机械复制国际站经营页面。中国站仍以备案主体与非经营边界为最高优先级：经营性 CTA、合作承接、报价收费、交易转化、客户招揽与直接商业导流必须过滤；其余适合个人知识分享的公开内容以“内容完整度优先”同步。

## 二、中国站长期定位

`qilylean.cn` 仅用于个人制造业知识与实践分享，可公开内容包括：

1. 精益生产、工业工程、标准化作业等通用知识；
2. 现场改善、流程优化、产能、质量、物流、布局等方法说明；
3. ERP、MES、APS、制造数据、AI 与数智工厂等学习内容；
4. 个人学习笔记、历史实践复盘、方法总结与知识模板；
5. 不涉及企业机密、人员隐私、客户保密信息的通用案例化说明；
6. 经公开边界检查后的个人职业实践、改善成果、阶段认可、颁奖／荣誉照片与学习记录；
7. 网站自身的备案、安全、版权、隐私和技术运行说明。

## 三、允许同步的内容

以下内容可从 `.com` 选择性同步到 `.cn`，但必须去除与个人知识分享无关的表达：

1. QilyLean VI 主色、字体层级、间距、卡片、导航、页脚等视觉基线；
2. 响应式、可访问性、速度、安全与稳定性优化；
3. 精益、IE、制造工程、数智工厂的知识文章与方法框架；
4. 经过脱敏与通用化处理的实践复盘；
5. 历史代表实践的“问题—方法—结果—沉淀”摘要，以及经过核验的改善前后数据；
6. 已公开或具备公开基础的个人阶段认可、颁奖／荣誉记录、学习纪念与相关图片；
7. 非经营性质的工具说明、学习资料与知识目录；
8. 搜索、结构化数据、站点地图等中国站独立技术配置；
9. 中国站专业文章、简报与资源目录均在本地域名完成阅读；除已明确指定的特殊模块品牌 LOGO 可返回国际站首页外，不设置通向国际站的文字按钮或商业相关跳转。
10. 跨域引用仅作为不产生点击导流的必要来源/SEO关系元数据保留，不得引入商业 CTA。

### 当前代表项目映射基线

国际站“代表项目”当前公开的 8 类内容，在中国站统一映射为个人实践档案，不直接复制商业项目页或商务入口：

1. 汽车电子精益体系、VSM、单件流与 SMED 标准化；
2. 300T 冲压机大型模具 SMED；
3. 智能模具库容量、载荷、库位与追溯；
4. 玻璃管保险丝切口与烧口工艺改善；
5. 新工厂／新产线 Factory Layout、物流与扩展边界；
6. 数智工厂数据治理、IT/OT 分层与工程验收；
7. 制造现场目视化系统设计与运行闭环；
8. 制造改善课题评审、风险确认与证据链。

同步原则是“国际站项目事实 → 中国站个人实践复盘”，而不是“国际站商业页面 → 中国站商业导流”。后续国际站新增代表项目时，应先通过公开边界检查，再补充中国站对应实践条目。

代表实践与荣誉素材进入 `.cn` 前必须同时满足：企业／客户名称与标识不构成未经授权的推广或背书；人员面部、姓名、联系方式等个人信息已按公开需要处理；订单、价格、料号、图纸、系统账号、内部参数等敏感信息不公开；团队／组织成果不得改写为个人独立创造；学习证书、平台记录和颁奖照片不得扩张表述为官方认证、政府资质或第三方推荐。

## 四、禁止同步 / 禁止发布

以下内容不得出现在 `qilylean.cn` 的正文、按钮、图片、二维码、元数据、结构化数据、页脚、脚本、隐藏元素、外链文案或搜索摘要中：

1. 项目合作、商务合作、业务承接、签单、签约、报价、收费、付款、合同、发票、收款等经营信息；
2. 咨询预约、获取方案、联系我们、业务入口、转化表单、销售线索收集等商业 CTA；
3. 服务套餐、服务范围、项目交付承诺、客户招揽、招商、代理、资源撮合、提成或分成信息；
4. 供应商、客户、合作伙伴联系方式及为第三方导流的经营入口；
5. 以 `.cn` 为跳板直接导向 `.com` 商业页面的链接、按钮、自动跳转、iframe 或代理展示；仅指定特殊模块中明确授权的品牌 LOGO 可返回国际站首页，禁止借此放置其他国际站经营入口；
6. 尚未依法取得的企业名称、企业身份、经营资质、商业主体信息；
7. 未经授权的企业／客户名称、Logo、人员可识别信息，以及订单、价格、料号、受限图纸、内部账号等不适合公开的资料；
8. 将团队／组织改善成果包装为个人独立成果，或将颁奖、学习记录、平台关联扩张为第三方官方背书；
9. 任何通过 CSS 隐藏、脚本延迟显示、参数触发或搜索引擎专用文本等方式潜藏的商业信息。

**原则：公开知识内容默认进入中国站；只有明确触及经营、交易、隐私、保密、授权或主体不匹配红线的内容才阻断。无法直接机械同步但知识价值明确的，改写为个人知识/实践版本后进入中国站。**

## 五、技术边界

以下内容必须保持双站独立：

1. `canonical`、robots、sitemap、搜索引擎验证与站长平台配置；
2. ICP、公安备案、主体信息等中国站法定信息；
3. 域名、证书、DNS、服务器、公网端口和环境变量；
4. `.com` 专属 SEO 与海外平台配置；
5. 依赖海外 CDN / 海外脚本才能正常首屏渲染的资源；
6. 中国站上线 Gate、内容合规 Gate 与自动化检查规则。

## 六、正式上线后的运行模式

1. `.com` 保持国际站独立运营；
2. `.cn` 只吸收适合个人知识站的内容；
3. 中国站新增内容必须先完成商业信息、隐私、版权、保密与数据安全检查；
4. `.cn` 独立做百度、国内网络性能、微信浏览环境与本地合规适配；
5. 不以中国站页面直接向国际站经营页面导流；仅保留经过白名单隔离的 Global Knowledge 与资源协同公开说明入口；
6. 未来企业正式成立并完成相应企业备案前，中国站的非经营性质不改变。

## 七、运维执行口径

后续每次 QilyLean 官网运维默认执行：

> **先判断目标站点 → `.com` 正常维护 → `.cn` 单独做个人站合规判断 → 允许内容才同步 → 分别回归与发布。**

即使 `.com` 的修改在视觉或技术上需要同步到 `.cn`，也不得把其中的商业文案、按钮、链接、元数据或隐藏信息一并带入。

## 八、不可回归红线

- `.cn` 不得成为 `.com` 的机械镜像；
- `.cn` 不得出现直接或潜藏的经营性信息；
- `.cn` 不得自动跳转或以主要入口导向 `.com` 商业页面；
- `.cn` 不得虚构企业主体、资质或经营身份；
- 中国站优先使用本地静态资源，避免海外链路成为首屏单点依赖；
- 所有发布继续执行视觉、性能、功能、移动端、微信环境和内容合规回归。


## 九、2026-10-10 全内容覆盖目标

中国站内容建设从“少量精选映射”升级为“国际站公开知识资产的大陆完整承接层”。

执行优先级：

1. 精选简报历史库：国际站已公开简报建立中国站本地副本与独立 canonical；
2. 知识文章：制造、IE、精益、质量、标准化、工厂规划、数智化专题逐篇建立中国站页面；
3. 术语、工具、程序文件与学习资料：以中国站本地目录和阅读页承接，不以跨域跳转代替；
4. 代表项目：保留事实、方法、数据与复盘，去除商业承接表达后进入个人实践档案；
5. 图片、图表与公开证据素材：符合授权、隐私和保密边界的同步到中国站本地资源；
6. 国际站新增公开知识内容时，中国站同步任务进入同一发布流程并做覆盖率审计；
7. 中国站每次发布输出“国际站公开内容总量 / 可同步总量 / 中国站已同步量 / 阻断量及原因”四项覆盖数据。

长期目标：在不改变中国个人备案性质、不引入经营性内容的前提下，使 `qilylean.cn` 成为 `qilylean.com` 公开制造知识资产在中国大陆的完整本地内容入口。


## 十、全站可视化与性能不可交换原则

本原则同时适用于 `qilylean.com` 与 `qilylean.cn`，优先级高于单纯的包体、带宽或加载耗时优化。

1. 可视化始终第一追求；中国站同步国际站内容时，不得以“国内加速”“减小发布包”“降低带宽”为理由降低图片、视频或网页视觉质量；
2. 图片不得默认降分辨率、降色彩、降细节或使用明显有损的二次压缩替代原始视觉资产；
3. 视频不得通过降低清晰度、码率、帧率或裁切关键画面来换取加载速度；
4. 页面提速优先采用缓存、本地化、同源代理缓存、懒加载、预加载、HTTP/2/HTTP/3、代码拆分、静态资源复用和增量发布；
5. 中国站需要本地承接国际站大体积媒体时，优先采用“原始字节质量保持 + 腾讯云侧缓存/预热 + 发布包与媒体资产解耦”的方式，不把大图反复塞进每次 HTML 发布包；
6. 任何衍生格式必须以原始高质量资产为基准，并能通过视觉回归或字节完整性检查证明未发生不可接受的质量下降；
7. 若“速度”和“视觉质量”发生冲突，优先保留视觉质量，再调整部署、缓存、服务器或传输架构解决速度问题。


## 十一、2026-10-18 非商业模块与影像资料同步口径

- 中国站一级导航与国际站的非商业专业栏目对齐：首页、履历主线、能力体系、改善工具、精益生产、代表项目、信任中心、知识资产、资源协同。精选简报保留在知识资产体系内，通过中国站本地年度索引访问。
- 国际站的项目合作、交易、签约、报价、付费、线索收集及相关经营性信息不进入中国个人站。
- “行走印记”原始工作现场、团队同行、出差足迹、生活远方资料归入双方“信任中心”；中国站仅使用已公开且符合授权、隐私和保密边界的内容。
- 图片使用原始字节质量的本地同源镜像缓存；导航、生成器、站点地图、搜索索引及 VI 验收必须保持一致。

## 十二、2026-10-22 双站发布与可视化生产闭环

1. 国际站生成器提交的静态页面不得使用 `[skip ci]`；否则页面虽已写入 Git，仍可能绕过中国站同步发布及下游验证。
2. 每次中国站 source-parity 发布必须先运行 `materialize-source-content-parity.py` 与 `validate-source-content-parity.py`，核对完整页面清单、源正文、样式、原始媒体字节、备案信息和中国站独立组件。
3. 中国站切换到候选版本后、正式接受版本前，必须直接访问 `https://qilylean.com` 与 `https://qilylean.cn` 运行 Playwright 可视化与交互回归，覆盖 320、390、820、1180、1600px，并验证页脚、备案行、联系方式二维码、知识卡片、搜索、导航和横向溢出。
4. 生产验证必须确认服务器 `cn-content-release.json` 的 `sourceCommit` 等于本次部署提交，或为其后代；不得用早期基准提交的祖先关系代替当前版本核验。
5. 任一生产视觉/交互门禁失败时，不得接受候选版本；由现有回滚看门狗恢复上一稳定版本，修复后重新发布。
6. 中国站的备案/公安备案、国内翻译器、个人主体边界与非商务内容必须保留；商务模块、报价、交易转化及用户明确排除的飞机模型不得克隆。图像和视频维持原始质量。
7. 对指向商业路由的锚点必须分离判断“目标链接”与“可见内容”：显式商业 CTA 与商业区块按规则过滤；非商业工程知识即使原链接指向 `/cooperation/`，也不得整块删除，应优先映射到中国站本地非商业落点，无法可靠映射时保留可见内容并移除商业跳转。生产验收逐页比对制造运营轴标签，确保“05｜数智固化 ERP/MES/APS/看板”等知识节点不因路由过滤而丢失。

## 十三、2026-10-26 首页小卡片与主理人 VI 防回退

- 非商业过滤后，“可信度来自边界清楚”须保留中国站适用的主标题与说明；唯一“证据分级”卡片占满整行。“先看交付逻辑”仅保留的两张卡片在桌面端等宽、移动端单列，不得遗留三/四列的空白槽位。
- 主理人模块为中国站保留的非商业专业协同内容：左侧人物照片、右侧两个全文卡片上下堆叠；生成器必须替换原始商业版主理人模块，而不能重复插入或清空该模块。

- 历史 Actions 失败记录作为追溯证据保留；仅以最新运行的发布、线上 DOM/VI 和备案/翻译/媒体全部验收通过作为整改闭环判据。

# QilyLean Site System V3｜全站竞争力与资产规范

> 生效日期：2026-08-12  
> 适用范围：QilyLean 全站首页、一级栏目、项目详情、知识资产、今日简报、工具、信任与合作页面。

## 1. 核心定位

QilyLean 不是“精益工具集合”，也不以页面数量、术语数量或装饰复杂度作为竞争力。

**核心价值：把制造现场变成可计算、可改善、可固化、可复用的组织资产。**

全站所有内容必须能够回到同一条制造运营资产闭环：

**现场事实 → 工程数据 → 精益改善 → 质量保证 → 数智固化 → 知识资产**

对应的六个竞争力维度：

1. **懂现场**：从 Gemba、产品、工艺、设备、人员、物流、质量与真实约束出发，不从模板倒推问题。
2. **能计算**：用 CT、TT、WIP、LT、UPPH、OEE、标准工时、产能、损失和交付数据建立共同工程语言。
3. **会改善**：围绕 PQCD 与瓶颈设计改善，优先 Pilot 验证，再决定标准化与复制。
4. **可固化**：把有效方法固化到 SOP、工艺、目视标准、主数据、系统规则和管理节奏。
5. **能证明**：明确项目背景、责任边界、数据口径与证据等级，不把预测值、团队成果或职业经历包装成商业承诺。
6. **可复制**：让个人经验升级为组织标准，可跨产品、产线、工厂和项目复用。

## 2. 内容层级

全站按以下优先级组织内容，禁止倒置：

1. **结论 / Why**：这个页面解决什么问题、创造什么价值。
2. **体系 / How**：采用什么工程逻辑、方法和闭环。
3. **证据 / Proof**：有哪些项目、数据、文件、图片或可核验结果。
4. **资产 / Asset**：形成了什么标准、模板、SOP、工具、系统或知识沉淀。
5. **边界 / Boundary**：哪些是职业成果、哪些是商业交付、哪些仍需现场验证。
6. **扩展 / Context**：AI、行走印记、资源网络等辅助资产，不与核心专业主线同权竞争。

任何页面如果只有“工具名 + 大段说明”而没有价值、方法、证据和资产，应按本层级重构。

## 3. 一级导视规范

一级导航只保留核心专业认知路径：

- 首页
- 能力体系
- 代表项目
- 改善方法
- 知识资产
- 履历主线
- 项目合作
- 信任中心

QilyLean AI、行走印记、产业资源协同网络、友情链接及其他扩展内容保留可达，但归入二级或内容内导视，避免与主专业链路争夺注意力。

## 4. 六类项目合作能力的统一逻辑

六类能力继续保持统一口径，不再出现“三大、四大、六大核心业务”混淆：

### 三类核心项目交付

1. 新工厂／新产线规划
2. 精益改善项目交付
3. 目视化项目设计与交付

### 三项数智化产品与技术能力

4. 数字化工厂
5. APP 软件开发
6. 专业官网建设

六类能力不是并列菜单，而是同一制造业务逻辑从现场、工程、管理延伸到系统、软件与数字资产的结果。

## 5. 证据与可信度规范

### 5.1 四类证据状态

- **已核定**：有正式核算、签字、系统记录或等效证据。
- **已验证**：通过现场实绩、对比数据、试点结果或可追溯记录验证。
- **阶段估算**：基于当前阶段数据测算，必须明确假设和未完成项。
- **经验陈述**：用于说明经历或方法，不作为已实现收益承诺。

### 5.2 必须分开的资产

- 历史任职企业中的职业成果；
- 跨部门／团队共同成果；
- QilyLean 商业签约项目；
- 个人研究、公开知识与演示样例；
- AI 辅助生成、整理或表达的内容。

禁止把职业成果描述成 QilyLean 品牌营收，禁止把团队成果描述成个人独占成果，禁止把未授权客户信息用于商业背书。

## 6. 视觉系统

### 6.1 品牌色

- 深青绿 `#0f4b5a`：专业、工程、主结构。
- 深青黑 `#073c47`：深层结构与高对比背景。
- 品牌金 `#caa15f` / `#ffe39b`：基准线、价值、关键入口。
- 品牌红 `#9e4a34`：风险、异常、纠偏与需关注信息。
- 白色、浅绿、灰绿：中性信息载体。

不新增无业务语义的彩虹色、紫色、荧光色主题。

### 6.2 风格

关键词：**工业工程、制造现场、数据基线、克制、精确、可信。**

- Hero 使用深青绿工业蓝图式背景，可使用低透明网格表达工程基准，不使用喧宾夺主的大面积装饰图形。
- 卡片以四边界、轻阴影、左侧或顶部基准线表达层级；静态卡片不做无意义浮动。
- 按钮不全站药丸化；常规圆角 8–12px，关键动作有清楚四边界。
- 金色只用于关键价值、当前状态和基准线，避免全页面“发金光”。
- 页面采用白 / 浅绿色块交替，不把所有信息都塞进卡片。

## 7. 排版与响应式

- 正文可读宽度优先，不因“填满屏幕”牺牲阅读舒适度。
- PC 主内容轴约 1240px；长段正文建议 920px 左右。
- 手机版左右至少保留约一个汉字宽度的有效视觉留白，并兼容 safe-area。
- H1 只表达当前页面唯一主结论；H2 表达章节问题；H3 表达方法或资产对象。
- 英文 kicker 只用于辅助层级，不替代中文主标题。
- 禁止为了追求对齐强制拆开中文短语；移动端优先自然换行。

## 8. 交互与导视

- 可跳转元素必须有 hover / focus / active 反馈。
- 静态信息块不得伪装成可点击卡片。
- 当前一级栏目必须有可识别状态，使用边界与品牌金基准线，不使用大面积跳色。
- 一级落地页显示制造运营资产价值轴，帮助访问者理解页面在整体体系中的位置。
- “返回上一层”遵循栏目父级，不直接无条件跳首页。

## 9. 性能与维护

- 优先修改现有中央 VI、导航、信息架构与发布源，不再为单一页面问题连续堆叠新的补丁 CSS/JS。
- 新增规则必须能说明：解决哪个全站问题、覆盖哪些页面、是否会与旧层冲突。
- 视觉调整不得以牺牲首屏加载、背景音乐连续性、移动端浏览、SEO 或无 JS 可索引性为代价。
- 首页核心价值与六类能力必须保留静态 HTML，避免搜索引擎源代码与客户端呈现两套口径。

## 10. 发布前门禁

每次全站级改动至少确认：

1. PC / 平板 / 手机三端标题、留白、卡片与按钮是否可读；
2. 一级导航是否一致、当前栏目是否正确；
3. 静态 HTML 与运行时口径是否一致；
4. 六类项目合作能力名称是否统一；
5. 证据等级、责任主体与商业边界是否被误改；
6. 今日简报、术语、知识资产统计是否仍来自统一数据源；
7. 背景音乐、悬浮工具、分享与联系功能是否被破坏；
8. `test:seo`、`test:visual`、`test:maintenance` 等现有自动校验是否通过。

---

**全站最终判断标准：访问者应在最短路径内回答六个问题——QilyLean解决什么问题、为什么这样解决、能力如何组成、证据在哪里、能形成什么资产、合作边界是什么。**

# 2026-08-27 首页飞机模型回退与首屏卡顿事故检讨及 CAPA

## 一、事故事实

2026-08-27 首页发生视觉基线回退：用户已经确认并要求长期使用的最新版飞机模型，被 V4 自动构建流程重新覆盖为历史飞机模型。截图可见旧模型主机翼存在明显透明/透出海浪的视觉问题，直接违背 QilyLean “可视化效果第一、已确认视觉成果不得擅自回退”的长期管理要求。

同时，首页飞机主视觉使用 1672×941、2,390,318 bytes 的 PNG 作为首屏高优先级资源，虽然清晰度得到保证，但在没有现代格式传输副本的情况下增加首屏传输负担，形成明显加载卡顿。

右下角全站悬浮 Dock 的文字颜色此前也没有被作为品牌级不可回退基线固化，存在后续样式覆盖风险。

## 二、检讨与责任

本次事故不是用户表达不清，而是变更控制失效。

1. **擅自突破已确认视觉基线**：自动构建脚本仍保留从历史分支抽取旧飞机模型的逻辑，使自动化流程拥有覆盖用户已确认主视觉的权限。
2. **SSOT 定义不彻底**：虽然存在最新版 `官网首图.png`，但构建流程没有把它定义为唯一权威源，导致“最新版源图”和“历史构建资产”并存竞争。
3. **防错门槛不够**：旧校验只关心格式、尺寸和最低文件大小，没有校验来源指纹、字节一致性和禁止历史源回灌。
4. **性能与画质没有分层管理**：直接把 2.39 MB PNG 作为首屏唯一传输资源，没有采用“原图不可变 + 高质量现代格式派生”的方式兼顾画质和速度。
5. **完成判定过早**：未把“构建后最终生产物、GitHub Pages 部署、真实首屏资源来源”作为一个完整闭环后再宣告完成。

对此，后续任何自动化脚本不得再以“构建便利、历史基线、缓存修复”等理由覆盖用户已经确认的视觉资产。

## 三、根因

### 3.1 直接根因

V4 Build 曾存在如下危险逻辑：从历史分支 `c919-approved-20260826` 拉取 `qilylean/c919-strategy-hero-v14.png`，并写入首页生产飞机资产。这一逻辑直接造成旧飞机模型重新进入生产环境。

### 3.2 系统根因

- 主视觉缺少唯一 SSOT + 指纹锁定；
- 构建脚本拥有不必要的跨历史分支取图权限；
- 缺少“禁止旧模型回灌”的 CI Gate；
- 缺少首屏图片传输预算 Gate；
- 缺少品牌 Dock 字体颜色不可回退 Gate；
- 视觉变更没有执行“用户确认版冻结”原则。

## 四、立即整改

1. **最新版飞机模型唯一化**
   - 根目录 `官网首图.png` 定义为飞机主视觉唯一 SSOT；
   - 锁定 Git Blob：`e67ad0ac7881da8e0fdbf6041fb9858882204ac4`；
   - 锁定尺寸：1672×941；
   - 锁定 PNG 原图字节数：2,390,318 bytes；
   - 生产 PNG 回退副本必须与 `官网首图.png` 逐字节一致。

2. **彻底关闭旧模型自动回灌路径**
   - 删除 V4 Build 中从 `c919-approved-20260826` 拉取历史飞机模型的执行逻辑；
   - CI 明确禁止任何可执行 `git fetch ... c919-approved-20260826` / `git show ... c919-strategy-hero-v14.png` 回灌动作；
   - 旧模型名称可以出现在事故文档或禁止规则中，但不得再成为运行时资源来源。

3. **首页性能整改但不牺牲画质**
   - `官网首图.png` 原文件一字节不改；
   - 由 SSOT 自动生成 Q98 WebP 高质量传输副本；
   - 浏览器优先加载 WebP，PNG 仅作兼容回退；
   - WebP 必须由当前 SSOT 在 CI 中自动生成，不允许人工上传另一架“相似飞机”替代；
   - WebP 设定 180 KB～1.6 MB 传输预算，低于下限视为可能过度压缩，高于上限视为性能失控。

4. **右下角悬浮 Dock 全站金色字体**
   - `首页 / 回顶部 / 回上一层 / 本站搜索 / 分享当前页 / 联系我们` 统一使用金色 `#ffe39b`；
   - normal / hover / focus / active 状态均保持金色文字；
   - CI 增加 Dock 金色身份 Gate，防止其他公共样式再次覆盖为白色。

5. **旧资产清理原则**
   - 主分支及生产路径不得继续引用旧飞机模型；
   - 明确无引用、明确属于被淘汰飞机版本的生产资产应删除；
   - “无关图文附件”不得凭文件名猜测后盲删，必须先确认无业务、证据、项目、SEO、分享或下载用途再删除，避免以清理名义造成第二次内容事故。

## 五、预防措施 / Poka-Yoke

### P1｜用户确认版冻结
任何被用户明确确认“采用、保留、作为最新版”的首页主视觉，默认进入冻结状态。除非用户再次明确授权更换，自动化、CI、缓存修复、性能优化均不得改变图像内容、构图、机型、文字布局和视觉语义。

### P2｜视觉资产单一事实源
首页飞机模型只认 `官网首图.png`。所有 WebP/AVIF/缩略图只能从它派生，不允许另一张历史图片或“批准分支”成为平行事实源。

### P3｜来源指纹 Gate
CI 同时检查：
- SSOT Git Blob 指纹；
- PNG 字节一致性；
- 尺寸；
- 文件格式；
- 生产 HTML 引用；
- 是否出现被淘汰模型的活动引用。

任一不符，禁止发布。

### P4｜历史回灌阻断 Gate
活动构建脚本中只要再次出现从旧飞机分支/旧模型文件提取生产图片的可执行命令，CI 直接失败。

### P5｜首屏性能 Gate
保持“原图零损伤归档 + 高质量现代格式传输”的双层结构。性能优化只能改变编码与传输方式，不得改变用户确认的图像本体。

### P6｜品牌 Dock Gate
Dock 金色文字作为全站品牌视觉基线，写入公共 CSS 和 V4 Build 校验，不允许页面级样式随意覆盖。

### P7｜变更范围隔离
SEO、sitemap、翻译、联系模块、部署流程等非飞机视觉任务，不得顺带重写飞机主视觉资产。跨模块写入必须有明确的必要性和回归验证。

### P8｜完成判定升级
以后同类整改只有同时满足以下条件才允许报告“已完成”：
1. 源码规则通过；
2. V4 Validate 通过；
3. V4 Build 通过；
4. 生成物再次验证通过；
5. GitHub Pages 部署成功；
6. Deploy Verify 通过；
7. 最终 HTML 指向最新版 SSOT 派生资源；
8. 不存在活动旧模型回灌路径。

- [x] 全站悬浮 Dock 文字统一金色并受 CI Gate 保护；

## 七、长期原则

**自动化只能保护用户确认的设计，不能替用户重新决定设计。性能优化只能优化传输，不能改变视觉本体。任何“修一个问题、制造另一个问题”的跨模块副作用，均视为不合格变更。**

# 2026-08-27 首页飞机模型回退事故检讨与防错计划

## 事故结论

本次首页飞机主图被回退为旧模型，属于构建链路越权覆盖事故。用户已经确认的最新首页飞机模型 `官网首图.png` 本应作为唯一权威源（SSOT），但 V4 Build 仍保留历史逻辑：每次构建从 `c919-approved-20260826` 分支取出 `qilylean/c919-strategy-hero-v14.png` 并覆盖生产主图，导致旧模型重新进入首页。

## 责任检讨

1. 未把用户最新确认版本设为最高优先级 SSOT，允许历史构建逻辑继续覆盖最新成果。
2. 在处理 CI 时扩大了变更边界，却没有完成“旧资产 / 旧发布器 / 旧分支引用”的冲突排查。
3. 没有为首页关键视觉资产建立“源文件 SHA 一致性 + 禁止旧分支引用 + 生产文件字节一致性”的三重防回退门禁。
4. 对首屏性能只关注加载策略，没有先消除重复物化、错误缓存与旧资产覆盖链路，造成无效构建和用户感知卡顿风险。

## 立即整改

- `官网首图.png` 继续作为最新首页飞机模型唯一权威源，尺寸、清晰度、图中文字及既有渐变效果不做再创作、不压缩降质。
- 生产文件 `assets/qilylean-aircraft-hero-approved-20260826.png` 必须与 `官网首图.png` 字节完全一致。
- 删除 V4 Build 中从 `c919-approved-20260826` / `c919-strategy-hero-v14.png` 回灌旧图的逻辑。
- 更新首页主图缓存版本，只使用一个生产图片 URL，保持 `loading=eager + fetchpriority=high + decoding=async`，不增加 picture/srcset/JS 换图链。
- 清理当前仓库仍存在的旧飞机模型、Base64 中间附件及无效副本；历史 Git 提交不做破坏性重写。
- 全站右下角悬浮功能模块文字统一为金色，背景、尺寸、位置、拖动/归位和交互反馈保持既有统一规范。

## 永久预防规则

1. **单一真源**：首页飞机模型只认 `官网首图.png`；任何工作流不得从历史分支、历史文件名或临时附件替换生产主图。
2. **SHA 门禁**：CI 校验权威源 SHA；生产目标必须与权威源字节一致，否则立即失败。
3. **旧源禁入**：活动 workflow / script 中出现 `c919-approved-20260826`、`c919-strategy-hero-v14.png` 等历史回灌引用即失败。
4. **视觉变更边界**：未经用户明确要求，不得改变已确认主图的尺寸、清晰度、主体、文字、二维码和渐变效果。
5. **性能非破坏原则**：优先通过单一资源、缓存版本、预加载优先级、避免 JS 重复换图来提速；不得通过降低图片质量换速度。
6. **资产治理**：保留“权威源 + 生产别名”两份必要文件；废弃模型、中间 Base64、重复副本从当前树移除。
7. **全站 Dock 统一**：悬浮功能模块颜色、字号、尺寸、顺序、交互反馈由公共样式统一管理，页面不得私有覆盖。
8. **发布闭环**：关键首页视觉修改必须经过 source guard → visual guard → build → Pages deploy → 主分支再核验五步闭环。

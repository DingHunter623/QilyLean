## 1. 适用范围：全站

本规范所称“全站”，唯一解释为：

- **国际站：`qilylean.com`**
- **中国站：`qilylean.cn`**
- 两站共享的品牌 VI、导航、字号、字重、模块宽度、留白、页脚、移动端适配、图片/视频质量、内容结构、公共组件及交互逻辑；
- GitHub 源码与版本管理、自动化构建与发布、腾讯云中国服务器、国际站托管环境、Nginx、缓存、搜索引擎、同步、备份与回滚链路。

“全站统一”不等于两个站点机械复制。视觉标准、内容质量、专业表达与品牌口径统一；中国站与国际站因备案主体、用户地域、网络环境、商业边界不同，允许在合规内容、链接、服务入口与部署架构上保持必要差异。

## 2. 最高优先级：可视化效果第一

QilyLean 全站任何运维，首先保证用户实际看到的页面具备高质量、清晰、稳定、统一、专业的视觉体验。

### 2.1 图片

- 清晰、比例正确、色彩准确、细节完整；
- 关键证据图、图表、工程截图必须可读；
- 不得为了提速、减小包体、节省空间而明显降分辨率、降画质、糊化、过度压缩或删除；
- 如采用 WebP/AVIF/响应式图片，必须以原始高质量资产为视觉基准，不能出现肉眼可见质量下降。

### 2.2 视频

- 保留高清源文件、关键画面、正常帧率与色彩表现；
- 不得为了加载速度而降低清晰度、码率、帧率，或裁切关键画面。

### 2.3 页面与移动端

- 桌面端、平板端、移动端必须稳定；
- 不得出现错位、遮挡、异常换行、横向溢出、Logo 失真、导航/页脚层级混乱；
- 已确认的浅金色、常规字重、模块宽度、导航/页脚字号与公共组件样式必须保持统一；
- 同类成熟模块已有样板时，以既定样板为准，不得局部标新立异。

### 2.4 高速浏览的正确含义

高速浏览是高质量体验的一部分，但**速度优化必须建立在“不降低图片、视频和网页视觉质量”的前提上**。

优先采用：

- 腾讯云本地化与服务器侧缓存；
- 浏览器长期缓存；
- Nginx 缓存与缓存预热；
- HTTP/2 / 条件允许时 HTTP/3；
- 首屏预加载、非首屏懒加载；
- 静态资源复用、代码拆分、增量发布；
- 文本类 Gzip/Brotli 压缩；
- 大型媒体与网页发布包解耦。

禁止采用：

- 降图片清晰度换速度；
- 降视频分辨率/帧率/码率换速度；
- 删除项目证据图、技术图表或专业说明换速度；
- 以“包体太大”“上传慢”为理由牺牲可视化质量。

> **原则：性能通过架构解决，不靠视觉质量让步。**

## 3. 前提要素：内容价值、信息含金量、专业维度、逻辑思维

“可视化第一”不等于只看外观。没有内容含金量、专业深度和逻辑结构的漂亮页面，不属于 QilyLean 合格交付。

### 3.1 内容完整

- 事实、方法、证据、数据、结论与上下文不得因改版、提速或代码精简被误删；
- 已确认有效的图片、概述、功能、证据、下载入口、技术说明不得在局部整改中被顺手删除。

### 3.2 信息含金量

页面应提供制造业用户真正能够：

- 理解；
- 判断；
- 复用；
- 对比；
- 落地；
- 行动

的信息，避免空泛口号、低价值堆砌与“为了有内容而有内容”。

### 3.3 专业维度

涉及精益、IE、PMC、ERP/MES、质量、工厂规划、自动化、标准化、数智工厂等内容时，应体现工程方法、指标、边界、参数、实施逻辑或验收逻辑。

### 3.4 逻辑思维

专业内容优先形成：

> **背景 / 问题 → 分析 → 方法 → 实施 → 结果 → 风险 / 边界 → 沉淀**

不得只有结论，没有分析；只有图片，没有说明；只有方法名称，没有适用条件与实施逻辑。

### 3.5 事实口径

名称、日期、版本、备案、功能、链接、技术参数、数据与品牌文案必须可追溯，不得凭印象随意改写。

### 3.6 可读性

信息密度高时，应通过：

- 标题层级；
- 摘要；
- 图表；
- 图片；
- 表格；
- 留白；
- 卡片；
- 重点强调

降低认知负担，而不是删除专业内容。

## 4. 全站 VI 与品牌一致性

- 统一品牌：**QilyLean｜启力精益**
- 中国站备案网站名称：**精益制造经验分享**，仅为备案与对应公开位置使用，不代表品牌更名；
- 中国站与国际站的字体、字号、字重、浅金色体系、模块宽度、内容轴线、导航、页脚、间距、移动端 Logo 等公共视觉标准统一；
- 视觉优化不得擅自改变页面框架、栏目语义、品牌文案或用户已经确认的操作习惯；
- 发现共性视觉缺陷时按全站整改；非共性问题采用最小差异修复。

## 5. 双站内容与合规边界

### 国际站 `qilylean.com`

- 国际品牌展示；
- 全球访问；
- 项目、知识、商业内容；
- 国际用户服务与合法商业入口。

### 中国站 `qilylean.cn`

- 制造知识；
- 精选简报；
- 实践复盘；
- 工具与方法；
- 备案允许范围内的个人制造业知识与实践分享。

中国站不得出现：

- 报价、收费、付款、合同、发票、签约等经营信息；
- 咨询预约、客户招揽、销售线索、直接商业 CTA；
- 未授权企业/客户 Logo、人员隐私、订单、价格、料号、受限图纸等不适合公开的内容。

国际站公开制造知识、精选简报、方法、工具说明、历史实践、学习资料等，应尽可能完整本地承接到中国站；需要转入中国站但包含商业语义的内容，先做个人知识化、实践化与脱敏处理。

## 6. 数据、存储与发布架构

### 6.1 代码与版本

GitHub 继续作为：

- 源码管理；
- 公共组件与生成脚本管理；
- CI / 构建；
- 版本历史；
- 审计；
- 回滚依据。

### 6.2 主数据与媒体存储方向

中国站所在腾讯云服务器逐步成为 QilyLean 的主数据与高质量媒体资产存储中心，优先承接：

- 高清图片；
- 视频源文件；
- PDF / 文档；
- APP 安装包；
- 内容数据；
- 媒体索引；
- 中国站生产数据；
- 国际站需要同步的公共资产主副本。

### 6.3 两站长期关系

- 中国站：优先从腾讯云本地读取，减少跨境依赖；
- 国际站：继续保持海外独立在线服务，不直接迁至中国大陆服务器；
- 国际站需要的媒体与内容，逐步从中国主数据源同步到海外分发层；
- 不建议国际站长期直接热链中国站资源；
- 大型媒体与网页发布包解耦，避免每次网页小改动都重复上传大文件。

## 7. 性能优化原则

性能优化的目标是：

> **更快地呈现同等或更高质量的内容。**

优先：

- 缓存；
- 本地化；
- 预加载；
- 懒加载；
- HTTP/2 / HTTP/3；
- 代码拆分；
- 静态资源复用；
- 增量发布；
- 服务端缓存与预热。

禁止：

- 通过明显有损压缩换速度；
- 删除内容换速度；
- 降低视频质量换速度；
- 改坏成熟视觉样板换所谓“代码整洁”；
- 让跨境资源成为关键首屏的单点依赖。

## 8. 发布与验收顺序

任何发布必须按以下顺序验收：

1. **视觉**：图片、视频、Logo、字体、字号、字重、布局、模块宽度、对齐、留白、移动端；
2. **内容**：事实、信息含金量、专业信息、证据、数据、上下文完整；
3. **逻辑**：导航、阅读路径、按钮、链接、下载、功能、数据流程；
4. **专业**：工程术语、方法、指标、边界、结论与技术含量；
5. **合规**：中国站备案/个人站边界与国际站商业边界分别通过；
6. **性能**：缓存、加载速度、媒体响应、脚本、服务器与兼容性达标，且无视觉降质；
7. **回归**：桌面端、移动端、主流浏览器、公共组件、生成源、相邻页面再次核验；
8. **生产验证**：线上真实 URL 验证通过后才算闭环。

> **提交成功、构建成功、上传成功、CI 通过，都不等于生产环境已经闭环。**

## 9. SSOT 与稳定维护

任何问题优先追溯：

1. 源码 / 数据源；
2. 公共组件；
3. 生成脚本；
4. CI / 构建与发布流程；
5. 最终生产页面 / APP / 产物。

禁止只改最终 HTML、APK 或临时文件而不修正真实生成源。

成熟模块进入稳定维护模式：

- 无明确价值不主动大改框架；
- 无明确需求不重新设计既有成熟视觉；
- 局部问题最小差异修复；
- 共性问题才扩大为全站修复；
- 所有关键变更必须保留回滚点。

---

## 10. 运维记录与生产追溯

运维证据链由三部分组成：

- GitHub：源码提交、CI、发布任务、失败原因；
- 服务器：`current / previous / releases` 与 Nginx 运行状态；
- 真实线上：生产 URL 与关键页面验证结果。

关键变更应记录：

- 时间；
- 版本 SHA；
- 变更摘要；
- 影响页面 / 资产；
- 发布结果；
- 健康检查；
- 回滚点。

---

## 11. 不可回归红线

- 不得把“全站”解释为只改其中一个站点；
- 不得为了提速、节省空间、减小发布包而降低图片、视频或网页视觉质量；
- 不得为了“简洁”删除高价值内容、技术细节、证据或专业逻辑；
- 不得擅自改变 QilyLean｜启力精益品牌名称、Logo、成熟视觉样板；
- 不得在中国站引入经营性 CTA、报价、收费、交易、客户招揽或直接商业导流；
- 不得因中国站合规要求机械删除国际站合法商业功能；
- 不得只验证桌面端、不验证移动端；
- 不得只看源码、不看生产页面；
- 不得把构建成功、上传成功、提交成功等同于线上闭环。

## 12. 最终执行口径

> **全站统一标准，双站独立合规；可视化效果第一，促进高质量浏览；内容价值、信息含金量、专业维度与逻辑思维是前提；性能通过架构解决；任何发布以生产环境真实闭环为准。**

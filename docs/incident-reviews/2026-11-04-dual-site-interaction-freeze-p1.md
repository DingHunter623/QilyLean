# QilyLean｜双站公共交互长时间卡死 P1 体系治理（2026-11-04）

- 故障单：[#799](https://github.com/DingHunter623/QilyLean/issues/799)
- 范围：国际站 qilylean.com、合规镜像站 qilylean.cn，全站顶部导航及正文可点击控件
- 状态：P1 根因未确认、生产未修复、连续 7 日观察失败，严禁标记闭环
- 参考：docs/QilyLean双站及数字产品全生命周期运维管理规范_V3.0_20261103.md（以仓库生效状态为准；不得把草案当作生产修复证明）
- 发布边界：绝不因网页卡死调整 Times26001 已签名 APK、包名、签名、备案或覆盖中国站的内容合规过滤

## 1. 事实与证据等级

1. 2026-11-03 两站导航/正文偶发点击后数十秒卡死，光标异常，期间地址栏不变。
2. 2026-11-04 用户在 Times26001 v1.1.15 正式版网页验收期间再次遭遇正文按钮卡死，不能确认是哪个按钮；**不允许因此仅修补某个按钮**。
3. 浏览器公开站点小样本重放没有复现，**不能否定用户复现、不能证明无故障**。
4. 国际站全站视觉对比度运行时对动态元素进行 style/class 监听、计算样式审查；国际站有多组公共事件监听/预取与共享导航运行时，中国站独立使用导航滑条、指针/尺寸/DOM 同步。以上是**风险假设，不是已确证故障根因**。
5. 同时考虑：浏览器主线程长任务、重排/重绘、共享事件回调竞争、下载链接阻塞、主文档导航请求 TTFB、浏览器插件/系统环境。地址栏未变不等价于网络未发起。

## 2. 系统级治理目标

不按菜单、按钮逐项补丁；按照**一份公共交互契约、清晰模块所有权、有界观察、性能失败证据、双站回归、独立生产验收**治理。

| 维度 | 必须执行的工程约束 |
| --- | --- |
| 原生导航 | 普通同源链接由浏览器原生导航，禁止横向/正文全局拦截或兜底反复 reload；下载/外链/片内锚点各有明确语义 |
| 事件所有权 | 一级导航只由导航运行时处理；分享/复制/下载由对应组件处理；Dock 有单一所有者；不得叠加全局捕获与重复绑定 |
| DOM 更新 | 视觉脚本优先静态 CSS；确需动态审查时范围限定在变动子树，且去重、节流、有每帧预算；观察器不得读写产生无界反馈 |
| 主线程 | 不应在 pointerover/click 同步执行全页 DOM 读取、逐节点 getComputedStyle、同步布局测量和无界重建 |
| 网络 | 预取仅响应真实导航意图，去重、限额、避开 APK/媒体；导航 TTFB 与事件循环阻塞必须分别统计 |
| 性能证据 | 记录点击前后路径、Long Task、心跳最大间隔、JS 异常、失败请求和 Chrome trace；不收集账户/手机号/剪贴板内容 |
| 品质保护 | 不降低图片视频质量、不删除有效内容，不改变已验收 VI、按钮标签及功能来换取速度 |
| 发布隔离 | 国际站公共运行时先实验、测试、验收；中国站独立构建、备案和非商务过滤审查，不直接照抄商业入口 |

## 3. 永久自动化诊断

新增只读脚本 scripts/audit-dual-site-interaction-stability-20261104.cjs 和 GitHub Actions 工作流 qily-dual-site-interaction-stability.yml：

- 国际站和中国站独立测试；1440/390px 两个视口，导航和正文链接多轮循环；Times26001 扫码弹窗单独循环。
- 浏览器在每一文档中采集心跳间隔（event-loop gap）、Long Tasks；监听页面 JS 异常与同源请求失败。
- **严重阈值**：event-loop gap ≥ 2500ms，或导航完成显著缓慢（动作累计 ≥ 15000ms）立即记录失败和诊断证据。网络慢不自动判作主线程问题。
- JSON 报告与失败截图保留，失败上下文额外保存 Playwright Trace（用于页面行为检查；必要时再用 Chrome DevTools Performance 主线程追踪）。
- 触发：手动、关联 PR、每日定时。**只有正式合并后才开始定时运行**；不因新建 PR 就宣称已有持续监控。
- 正常小样本测试不证明 P1 完全解决；失败测试需明确实际阻塞和可复现路径再修改源码。
- 测试中不得下载大 APK、上传数据、修改生产后台或强行跳转商业路径。

## 4. 可追踪的根因闭环步骤

**P1-01 复现与量化：** 取得同类故障的一次真实浏览器 Performance 追踪，或者 CI 取得同类事件循环卡顿与操作记录；对比鼠标点击事件、首个长任务起止、网络请求、unload 事件和主文档提交时间。

**P1-02 定位与责任边界：** 确定最小公共运行时集合，通过测试分支的 A/B 隔离验证（对比度审查、预取、导航滑动、分享、第三方脚本），而非在生产环境随机关闭模块。

**P1-03 结构治理：** 对确认存在无界/重复的观察器、事件绑定和全页同步样式计算实施有界化；对同一行为确立一个所有者，优先源头修复；修复需保留视觉与功能，不做 per-button 特例。

**P1-04 回归：** 国际站与中国站分别验证顶部导航、内容链接、锚点、扫码、分享、复制、下载说明、PDF 预览、浏览器返回等；桌面/移动、高频连续点击、页面刷新、前进后退缓存、慢网缓存环境。

**P1-05 上线与回滚：** 记录原始 SHA、PR、CI、正式发布 SHA、域名页面性能证据及回滚点；中国站按独立合规与部署门禁验收。

**P1-06 用户最终验收：** 从经确认的修复发布日重新起算，双站连续 7 天未出现相同卡死，再由用户反馈确认闭环。任何期间复发，观察窗口重置，Issue 保持打开。

## 5. 不能制造的结论

- “代码改了”“CI 绿了”“连续点击 N 次没问题”“一个按钮正常”都不是消除间歇性卡死的证明。
- 自动化的 2.5 秒/15 秒阈值是当前**诊断告警阈值**，不代表用户约定的全部体验或正式 SLA。
- Chrome trace 对实际用户环境（Mac、浏览器扩展、网络节点）有独立价值；当生产压测未复现时，不能凭猜测声称彻底解决。
- 该治理 PR 先加可审查的检查与证据链，不自动修改全站生产 JS，也不自动合并。

**验收口径：P1 根因可复现且解释清楚 → 系统层修复 → 双站实机回归 → 生产 7 天观察 → 用户确认关闭。**

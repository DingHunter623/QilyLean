## 0. 本次升级的核心决策

1. **国际站 qilylean.com 是 QilyLean 全球主站、唯一内容源（SSOT）和最高运营标准。** 品牌规划、内容策划、业务布局、产品规划、版本决策及网站标准均以国际站为准。
2. **中国站 qilylean.cn 是合规镜像站。** 只同步国际站中经审核允许在中国大陆公开的非商务信息，不独立另起品牌、内容主线或商业运营体系。
3. **双站统一品牌 VI、内容质量、专业标准和交互体验；域名、备案、SEO、部署、安全及合规规则分别管理。**
4. **APP 是独立数字产品线。** 不得把不同 APP、不同包名、不同备案、不同签名或历史测试工程混为一个产品。
5. **生产验收是唯一交付依据。** 代码提交、CI 通过、预览部署、安装包生成均不等于正式交付。
6. **质量优先。** 不以降低图片、视频、内容或页面品质换取速度、包体或部署便利。

## 1. 管理范围与规范层级

### 1.1 管理范围

- 国际站：https://qilylean.com/
- 中国站：https://qilylean.cn/
- 桌面 APP：中国站 Windows / macOS 客户端。
- Android APP：Times26001，以及经负责人明确批准的后续 Android 产品。
- 工程资产：GitHub 源码、公共组件、样式、脚本、内容源、媒体源、APP 工程、构建工作流、发布清单、服务器、域名、证书、缓存、日志、备份和回滚记录。

### 1.2 规范优先级

发生冲突时按以下顺序处理：

1. 国家法律法规、监管要求及已通过的备案信息；
2. 本规范 V3.0；
3. 国际站正式 VI 实现与经负责人确认的专项标准；
4. APP 产品专项规范、站点专项 Runbook；
5. 单次项目任务书、PR 说明及临时整改指令。

旧文件不得继续作为独立、平行的最高规则。专项文件必须标明适用范围，并服从 V3.0。

## 2. 双站治理架构

### 2.1 国际站：唯一主站与唯一信息源

qilylean.com 负责：

- 全球品牌形象、品牌叙事及统一 VI 的定义；
- 专业知识、工程实践、项目事实、精选简报和公开内容的源头维护；
- 国际业务信息及其独立合规管理；
- APP 产品介绍、版本规划、全球产品信息和主版本记录；
- 双站公共组件、设计规范、内容标准及技术架构的源头变更；
- 新页面、新模块、新媒体及新数字产品的首次设计和验收。

任何公共内容、公共样式或公共功能原则上先在国际站源头完成，再判断是否需要同步中国站。

### 2.2 中国站：非商务内容合规镜像

qilylean.cn 仅承接国际站已经公开、且经审核符合中国大陆个人知识分享边界的非商务信息。

允许同步的典型内容：

- 精益生产、工业工程、标准化作业、制造工程、数智工厂等专业知识；
- 非经营性质的精选简报、学习笔记、方法框架和工具说明；
- 已脱敏、已核验、具备公开条件的个人实践复盘；
- 不涉及客户机密、人员隐私、商业合同及未经授权背书的公开工程事实；
- 备案、隐私、版权、技术支持和网站运行所必需的公开信息；
- 经负责人明确批准的其他非商务内容。

中国站禁止出现：

- 项目承接、商务合作、签约、报价、收费、付款、合同、发票等经营信息；
- 咨询预约、业务招揽、销售线索收集、转化表单、招商、代理、佣金、分成；
- 具有经营目的的资源撮合、供应商入驻、客户导流、商业二维码和商业 CTA；
- 通过隐藏文本、脚本延迟、图片、二维码、元数据、搜索摘要或跨域跳转潜藏的商务信息；
- 未经授权的企业标识、客户信息、人员隐私、订单、价格、料号、内部图纸、账号或保密数据。

联系方式仅在备案、隐私、版权、技术支持、网站纠错等非商务必要场景下保留；不得将其包装为业务咨询、销售或项目承接入口。

### 2.3 内容同步流程

统一执行：

**国际站源头更新 → 内容分类 → 商务边界审核 → 版权/隐私/保密审核 → 中国站白名单确认 → 镜像生成 → 内容与媒体完整性校验 → 中国站独立 CI → 生产发布 → 双站实机验收。**

要求：

- 不允许无审核的全量自动复制；
- 不允许因为过滤商务入口而删除仍有知识价值的技术正文；
- 混合内容应保留非商务知识，单独剔除经营性模块、链接、二维码、表单和元数据；
- 不得通过 .cn 自动跳转、iframe、代理或隐藏链接，将用户导向国际站商业页面；
- 指向国际站的链接只有在目标本身属于公开非商务内容、且经白名单确认后才允许保留；
- 中国站不得独立发布与国际站主线冲突的品牌口径、业务定位或公共内容版本；
- 法定备案信息、隐私协议、国内搜索配置、国内网络适配等允许作为中国站必要的本地差异项。

中国站每次同步应留存：源页面、源提交 SHA、目标页面、内容分类、过滤原因、媒体校验结果、发布版本及生产验收证据。

### 2.4 国际站未完成大陆备案期间的边界

国际站继续作为全球主站独立运营。不得把中国站当作国际站商业业务的代理入口、跳板或规避备案的技术通道。涉及中国大陆用户、服务器、域名、APP 服务和分发的具体活动，应按其实际业务和适用监管要求单独核验，不以另一站点的备案替代。

## 3. 统一品牌 VI 与可视化规范

### 3.1 最高原则

**可视化效果第一；内容价值、专业含金量、专业维度和逻辑思维是前提。**

漂亮但空洞的页面不合格；内容专业但无法清晰阅读的页面也不合格。

专业内容优先形成：

**背景/问题 → 分析 → 方法 → 实施 → 结果 → 风险/边界 → 资产沉淀。**

### 3.2 公共视觉基线

双站公共视觉以国际站正式 VI 为源，公共组件不得在中国站另行设计一套。

站点品牌色基线：

- 深青绿：#0F4B5A
- 深青黑：#073C47
- 辅助青绿：#178B94
- 品牌金：#CAA15F
- 浅金：#FFE39B
- 风险/纠偏色：#9E4A34
- 白色及浅青灰作为内容承载底色。

站点主内容轴及响应式留白，以 V2.0 已确认的权威数值为准：

- 内容轴：1180px
- 安全边距：clamp(18px,2.2vw,56px)
- 正文长文阅读宽度按内容类型控制，不得为填满屏幕无限拉宽。
- 新增/改造的普通文章、独立专题与关于我们页面须先继承既有 **1180px 公共内容轴**，正文承载容器与同页面模块对齐；不得擅自新设 920px 等次级限宽，导致标题、文章及其他模块左右边界不一致。确需窄幅阅读排版的专项页面必须先明确授权并做跨终端目视化验收。
- **可视化永远是第一验收维度之一**：新建与整改同标准，验证首屏、正文宽度、字体层级、留白、视觉对齐、移动端溢出及公共导航/页脚，且必须在真实生产站点验收，不得以源码或 CI 通过代替可视化闭环。

排版基线继承 R8 已确认尺度：

- H1：clamp(42px,4vw,64px)
- H2：clamp(30px,2.7vw,44px)
- H3：clamp(22px,1.55vw,27px)
- 正文：18.5px
- 注释/说明：17px
- 一级导航：20px

上述值为公共基线；只有负责人明确批准的专项设计才能改变，并必须双站同步评估。

### 3.3 VI 权威冲突处理

当前代码中存在 site-visual-authority-r8.css 的 1180px 轴线与 site-vi-standard-v4.css 的 1240px 容器设置不一致的情况。V3.0 明确以 **1180px** 为现行权威值。

在完成代码统一、双站实际渲染验证及自动门禁修复前，不得宣称 VI v4 全面验收通过；不得通过删除检查项、跳过 CI 或降低门禁标准来制造通过结果。

### 3.4 图片、视频与图文排布

- 使用真实、高质量、具有内容证明价值的图片和视频；
- 不得用低清示意图替换真实工程证据，不得擅自裁切关键结构；
- 图片比例、色彩、细节和文字必须清晰；
- 四张并列图片采用 2×2；三张同组图片优先一行排列；
- 同一行图片顶部对齐，图片下方文字概述统一沉底对齐；
- 图片尺寸应适配内容，不为机械等高而裁切主体；
- 全页图片如具备放大需求，点击查看原图，关闭按钮及 ESC 可关闭并恢复原浏览位置；
- 视频保留关键画面、合理帧率和原始视觉质量。

性能优化不得以明显降低分辨率、码率、帧率、色彩或删除内容为代价。

### 3.5 可读性与无障碍

- 正文与背景至少达到 WCAG AA 对比度要求；
- 关键数据、标签、按钮、图表必须在桌面和手机端清晰可辨；
- 不得出现文字被背景吞没、红圈区域难辨、图标与文字重叠、图片和文字错位；
- 所有可点击元素必须具有 default、hover、active、focus-visible、disabled 状态；
- 动画原则上 180–220ms，不得通过改变尺寸造成布局抖动；
- 移动端不得依赖 hover 才能理解或操作。

### 3.6 公共交互红线

- 导航、搜索、分享、复制、返回、首页、外链、下载等公共交互双站统一；
- “分享当前”应同时完成系统分享动作、复制当前标题及完整网址，并给出清晰反馈；
- 所有外链必须明确目标与打开方式，不得伪装成本地导航；
- 当前页标识、菜单展开/收起、焦点和返回路径必须稳定；
- 不得因重复事件监听、脚本竞争、无限重绘或阻塞主线程造成网页卡死。

## 4. 内容与专业资产管理

### 4.1 内容质量

新增内容必须回答：

- 解决什么制造或工程问题；
- 依据什么事实、数据或现场约束；
- 使用什么分析方法和实施步骤；
- 如何验证结果；
- 适用边界和风险是什么；
- 最终沉淀了什么标准、工具、数据或知识资产。

### 4.2 证据分级

统一区分：

- 已核定：有正式核算、签字、系统记录或等效证据；
- 已验证：有现场实绩、试点结果或可追溯对比；
- 阶段估算：有明确假设、数据边界和未完成项；
- 经验陈述：用于说明经历和方法，不作为收益承诺。

不得把团队成果写成个人独占成果，不得把历史任职企业成果写成 QilyLean 商业营收，不得将 AI 生成内容包装为真实现场证据。

### 4.3 已验收资产保护

- 已通过用户验收的页面、内容、图片、视频、二维码、模块和功能默认进入稳定维护；
- 无明确价值不得反复调整已闭环细节；
- 局部问题采用最小差异修复；
- 共性问题才扩大为双站整改；
- 任何变更不得顺手删除已确认的有效内容、证据和功能；
- 失败的 PR、构建或视觉门禁不得触发已验收生产版本无依据回退。

## 5. 代码、数据、部署与基础设施

### 5.1 唯一技术源

GitHub 是源码、版本历史、公共组件、脚本、CI 和回滚依据的唯一代码源。

禁止：

- 直接在生产服务器修改后不回写 GitHub；
- 只修改生成后的 HTML、APK 或临时文件，不修正真实源文件；
- 使用来源不明、版本不明的二次打包产物；
- 将测试分支、历史 ZIP 或过期缓存包误作正式发布源。

### 5.2 双站部署边界

- 国际站继续保持其独立生产架构；
- 中国站使用独立的腾讯云服务器、Nginx、证书、DNS、缓存和发布链；
- 两站共用品牌和内容标准，但不得共用未经隔离的环境变量、服务器凭证或生产配置；
- 中国站优先使用本地静态资源，避免海外 CDN 或跨境脚本成为首屏单点依赖；
- 公共媒体可按原始质量同步，不得通过降低媒体品质解决跨境加载问题。

### 5.3 发布与回滚

中国站服务器发布采用独立版本目录与原子切换：

- releases/<release-id>
- current
- previous

发布前必须完成候选包完整性、Nginx 配置、备案信息、内容合规、健康检查和回滚准备。生产切换后验证真实域名 HTTPS、HTTP/WWW 规范化跳转、关键页面、资源加载和版本 SHA。

要求：

- 部署任务串行化，避免旧任务覆盖新版本；
- 不复用未经验证的旧 /tmp 发布包；
- 候选版本失败只回滚候选版本；
- 已经验收通过的生产版本不得因无关 PR 失败而回退；
- 保留足够的历史稳定版本和变更证据；
- 生产部署必须确认服务器版本对应本次预期 sourceCommit。

### 5.4 安全管理

- SSH 私钥、API Token、数据库密码、APP 签名密钥及其他 Secret 只能存放在受控 Secrets/密码库；
- 禁止将密钥、密码、Token、个人身份证明、服务器凭证提交到公开仓库；
- 公开仓库中的运维文档不得暴露不必要的公网 IP、登录用户名、内部网络拓扑和访问细节；
- 最小权限、最小开放端口、定期检查账号权限；
- 证书到期、DNS 变化、服务器异常、备份失败必须有记录和告警；
- 涉及用户数据时遵守最小采集、明确用途、最短必要保存及隐私政策一致原则。

## 6. 性能与稳定性

性能目标是：**更快呈现同等或更高质量的内容。**

优先手段：

- 首屏关键资源合理预加载；
- 非首屏图片和视频按需加载；
- 浏览器缓存、Nginx 缓存、缓存预热；
- HTTP/2，条件允许时 HTTP/3；
- CSS/JS 拆分、静态资源复用、增量发布；
- 文本类 Gzip/Brotli；
- 媒体资产与 HTML 发布包解耦；
- 避免第三方脚本阻塞主线程。

禁止通过降画质、删内容、删证据、降视频规格换速度。

稳定性检查覆盖：

- 首屏旧版本闪现、白屏、布局抖动；
- 菜单点击、路由跳转、返回、刷新和页面恢复；
- 重复事件监听、主线程长任务、脚本异常和资源加载失败；
- 浏览器缓存、Service Worker、CDN 缓存和版本更新；
- 桌面端、平板端、手机端及微信浏览环境。

## 7. SEO、备案与合规

### 7.1 两站独立管理

两站的 canonical、robots、sitemap、搜索平台验证、域名证书和备案信息分别维护，不得因内容镜像而错误合并索引或备案身份。

### 7.2 中国站

- 网站备案信息必须与实际主体、网站名称和内容性质一致；
- 页脚展示已取得的网站备案信息及有效查询链接；
- 公安联网备案按实际适用要求办理，取得编号后再公开展示；
- 网站内容持续符合个人非商务知识分享边界；
- 国内搜索抓取开放不等于已收录，必须区分“可抓取、已提交、已收录”。

### 7.3 APP 备案

APP 备案与网站 ICP 备案是不同事项，不能互相替代。APP 在中国境内提供互联网信息服务，应按适用规定履行 APP 备案；APP 备案信息发生变化时，应核验并办理相应变更。APP 应在显著位置展示备案编号，并提供备案查询入口。

官方依据：

- 工信部《关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105号）：https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html
- 工信部政策解读：https://www.miit.gov.cn/jgsj/xgj/hlwgl/art/2023/art_564bf0759d7e41d5b4aa8ce4996b9e84.html

## 8. APP 产品线治理

### 8.1 通用规则

每款 APP 必须有独立产品档案：

- 产品正式名称、包名/Bundle ID、版本号；
- 代码仓库、构建工作流、源提交 SHA；
- 备案名称、备案编号、服务域名；
- 隐私政策、用户协议、技术支持地址；
- 权限清单、SDK 清单、网络访问目的；
- 图标源、签名证书指纹、SHA-256；
- 测试记录、发布记录、已知问题和回滚方案。

APP 之间不得共用包名、备案编号、版本台账或签名密钥。统一品牌图标不等于产品合并。

### 8.2 Times26001｜个人时间管理

产品定位：面向工业工程、现场改善与时间研究场景的专业测时工具，由 QilyLean｜启力精益开发。

- Android 包名：com.qilylean.times26001；
- 独立产品、独立代码仓库、独立版本与签名；
- 当前策略：**不提交应用商店；仅计划通过官方官网发布正式签名 APK**；
- 未经负责人重新决定，不启动应用商店 AAB 发行流程；
- 官网分发包必须使用 Release 正式签名，不得使用 Debug 包或 QA 测试包；
- 固定签名密钥必须长期安全保存，版本升级沿用同一签名体系；
- 每次发行提供 APK、SHA-256、版本说明、签名证书指纹和源提交记录；
- 不得静默下载、自动安装或绕过用户操作更新；
- APP 内备案编号、查询入口、隐私政策、用户协议、技术支持必须与实际版本和备案资料一致。

**发行阻断项：** 当前备案记录中的服务名称为“个人时间管理”，代码配置中的 APP 显示名称为 Times26001。正式 APK 发布前必须以备案平台、接入商确认及最终安装包实测为依据，核对名称、包名、服务域名、隐私政策和备案信息的一致性；不得自行假定名称差异无需处理，也不得未经确认擅自更改备案名称。

官方产品信息与版本决策归国际站主站管理。实际 APK 下载地址、APP 服务域名和中国大陆分发范围，必须与已通过的 APP 备案记录核对；中国站只允许展示经审核的非商务信息，不自动镜像 APK 二进制或商业入口。

### 8.3 QilyLean 中国站桌面客户端 V1.0

- 独立工程：desktop/qilylean-cn；
- 技术路线：Tauri 2；
- 内容源：https://qilylean.cn/，在线呈现中国站实时内容；
- Windows：Windows 10/11 x64，NSIS 安装包；
- macOS：Apple Silicon arm64 与 Intel x64，分别生成 DMG；
- 首版不做离线内容镜像、账号体系、托盘、自动更新或本地内容重建；
- 网站内容更新在客户端下次加载时体现；原生代码更新需重新构建安装包；
- 远程网站不得获得不必要的 Tauri 本地系统 API 权限；
- 中国站内 HTTPS 导航留在客户端；外部站点交给系统默认浏览器；
- 桌面 APP 是网站的独立访问壳，不另造一套内容、VI 或导航。

当前策略：先完成安装包、安装/运行/退出/卸载和跨系统实机验证；是否进入应用市场另行评估，不作为当前必达目标。CI Artifacts 或未签名安装包只属于测试交付，不得标记为正式发行。

正式公开分发前，应评估 Windows 代码签名、macOS Developer ID 签名及公证要求，并向用户清楚说明安装来源和系统安全提示。

### 8.4 Android 中国站 APP 的正式方向

未来如继续开发 QilyLean 中国站 Android APP，正式方向是：

**直接呈现 qilylean.cn 的轻量网站封装。**

要求：

- 与中国站网站内容、字体、字号、色彩、布局、VI、导航和交互保持一致；
- 独立 APP 工程，不修改双站生产代码；
- 首版在线访问，不做离线阅读；
- 网站更新在下次加载时体现，原生代码变更才重新发布安装包；
- 备案名称、包名、服务域名、权限和隐私信息单独管理。

历史 Android 桌面启动器/Launcher 工程不得误标为上述正式版，也不得未经重新确认就作为中国站正式 Android APP 发布。

### 8.5 历史 APP 与独立产品

QilyLean Home、QilyLean CN Home、Times26001 等项目必须按各自包名、产品定位和历史版本独立管理。历史测试版、旧启动器、实验性 APK 不得混入当前正式下载入口。

### 8.6 统一品牌图标

APP 使用 QilyLean 统一 Q 图标源，保持以下视觉一致：

- Q 主体：#126478
- 深色内核：#081E20
- 红色圆点：#F03A39
- 外围透明。

商店图标（如未来另行批准上架）、安装包内置图标、安装确认页、桌面图标和系统应用信息图标必须来自同一批准源。不得为不同 APP 私自另造主品牌图标。

## 9. APP 与网站发布 Gate

任何网站或 APP 正式发布必须完成以下 Gate：

1. **需求 Gate：** 目标、影响范围、产品边界和验收标准明确；
2. **合规 Gate：** 内容、备案、隐私、版权、主体、服务域名和权限申报通过；
3. **源代码 Gate：** 源文件、依赖、版本、构建配置可追溯；
4. **构建 Gate：** CI、静态检查、单元测试、构建和包信息校验通过；
5. **视觉 Gate：** 桌面、平板、手机或对应操作系统实际呈现符合 VI；
6. **交互 Gate：** 导航、按钮、返回、刷新、权限拒绝、网络恢复等场景通过；
7. **安全 Gate：** Secret、权限、SDK、网络访问、签名和隐私边界通过；
8. **实机 Gate：** 对应系统和架构完成真实安装、启动、运行、升级/覆盖、卸载测试；
9. **发布 Gate：** 正式签名、SHA-256、版本说明、发行清单和备份齐备；
10. **生产 Gate：** 正式域名/正式安装包验证通过，记录实际版本和证据。

任何 P0/P1 Gate 失败，不得发布或标记闭环。测试包不得冒充正式包。

## 10. 运维变更、故障与验收

### 10.1 标准流程

**发现问题 → 收集证据 → 确认根因 → 最小化整改 → 预生产验证 → 自动化回归 → 生产发布 → 真实环境验收 → 观察 → 闭环归档。**

### 10.2 问题分级

- P0：全站不可用、数据泄露、签名密钥泄露、严重合规事故；
- P1：核心导航/交互故障、关键功能不可用、错误版本覆盖生产；
- P2：重要内容缺失、明显视觉错位、移动端异常、性能显著退化；
- P3：不影响使用的局部细节和低优先级优化。

### 10.3 验收证据

每次重要变更至少记录：

- 变更前后截图或录屏；
- 源提交 SHA、构建 ID、发布版本；
- 影响页面/APP、设备、浏览器和视口；
- 自动化测试结果；
- 生产 URL 或安装包实测结果；
- 失败情况、回滚版本和最终结论。

不得以“我已经提交”“CI 显示成功”“文件已上传”代替生产验收。

### 10.4 回归矩阵

网站至少覆盖：1920、1680、1440、1366、1180、1024、834、820、430、390、375、360、320px 等关键宽度；实际测试可按设备与页面类型抽样，但首页、导航、页脚、关键内容、图片/视频、公共交互必须覆盖。

APP 按目标 OS、CPU 架构、系统版本、屏幕尺寸和权限场景制定矩阵。

## 11. 当前已知整改与观察事项

以下项目是规范升级时发现的现状，不得因为写入规范就视为已经整改完成：

1. **内容轴冲突：** R8 的 1180px 与 VI v4 的 1240px 设置需统一为 1180px，并完成双站视觉回归。
2. **Times26001 名称一致性：** 备案服务名称“个人时间管理”与构建配置显示名称 Times26001 需核验。
3. **Times26001 正式签名：** 当前正式发行工作流缺少签名 Secrets；QA 测试构建成功不代表正式签名包已生成。
4. **版本台账：** 公开站点发行清单记录 v1.1.14，而私有工程已配置 v1.1.15；必须在正式发布前完成版本、包体、签名、SHA-256 和下载入口一致性核验。
5. **桌面 APP：** Windows/macOS 构建工作流已存在，但未签名 CI Artifacts 不得认定为正式发行。
6. **VI v4 Formal：** 历史工作流存在失败记录；须核对最新运行并修复真实失败项，不得绕过门禁。
7. **导航卡死观察：** 2026-11-03 双站曾出现菜单点击后光标持续转动、页面短时卡死且地址栏不变的现象。该问题处于根因排查/观察状态；按用户确认的一周观察窗口，只有连续一周未复现并经用户确认后才能关闭。排查应聚焦事件循环、重复监听、路由处理、主线程长任务、缓存/Service Worker 和第三方脚本，不得反复进行无证据的通用网络检查。
8. **公开运维信息：** 公开仓库的运维文件应持续脱敏，不得公开不必要的服务器公网 IP、登录用户名、SSH 私钥或内部访问细节。

## 12. 运维节奏

- 每次发布：完成全套 Gate、记录版本与生产证据；
- 每周：检查故障观察项、发布记录、域名/证书和内容同步状态；
- 每月：检查账号权限、依赖/SDK、备份完整性、APP版本台账和失效链接；
- 每季度：抽查备份恢复、回滚流程、APP签名密钥可用性及双站合规边界；
- 发生备案主体、域名、APP名称、包名、权限、SDK、服务内容或分发方式变化时，先进行合规影响评估，再实施发布。

## 13. 最终执行口径

> **国际站定义品牌、内容、产品和技术标准；中国站只镜像经过合规筛选的非商务信息。双站统一 VI 与专业质量，合规、部署和数据边界独立。APP 独立建档、独立备案核验、独立签名、独立验收。任何变更先证据、后整改；任何发布先验证、后放行；任何闭环必须以真实生产环境和实际安装结果为准。**

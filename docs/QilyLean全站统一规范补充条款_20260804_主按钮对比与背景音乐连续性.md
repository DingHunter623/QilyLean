# QilyLean全站统一规范补充条款｜深色首屏主按钮与背景音乐连续性

版本：V2026.08.04 R1  
生效日期：2026-08-04  
适用范围：QilyLean主站、全部导航模块、友情链接、行业资源入驻、独立分享页面及公共发布流程

## 1. 问题与根因

### 1.1 深色首屏主按钮

- 项目合作页“预约60分钟问题初筛”和行业资源入驻页“立即填写入驻资料”均属于深色首屏中的主行动按钮。
- 既有全站样式把深色首屏内普通链接统一设为浅金／白色文字，并同时使用 `-webkit-text-fill-color: … !important`。
- 该规则未排除主按钮，导致主按钮即使页面内已声明深色文字，仍可能被公共样式、缓存或加载顺序覆盖成浅底浅字。
- 单页补丁不能构成闭环；必须建立全站公共保险层，并在全部公开HTML中使用独立缓存版本加载。

### 1.2 背景音乐

- 友情链接页面未加载背景音乐脚本，因此从其他模块跳转后音乐直接消失。
- 旧版音乐采用“页尾加载器→二次加载核心脚本”的两段式结构，启动较晚。
- 旧版恢复逻辑在设置播放位置后等待 `seeked`，最长可等待约700ms再执行播放，放大了跨页面跳转的停顿。
- 发布脚本只更新已有音乐引用，不会为缺失页面补装，因此新增页面或独立模块容易再次漏装。

## 2. 深色首屏主按钮统一规则

### 2.1 视觉

- 正常状态：浅金实底 `#FFD36A`、深色文字 `#332100`、浅色边框、无文字阴影。
- 悬停／键盘聚焦／按下状态：浅金高亮底 `#FFE39B`、深色文字 `#201400`、白色边框和清晰焦点环。
- 正常状态文字与背景对比度约为10.88∶1；高亮状态约为14.39∶1。
- 必须同时覆盖 `color` 与 `-webkit-text-fill-color`，防止浏览器文字填充色继承旧规则。
- 主按钮及其内部子元素不得降低透明度、使用滤镜或文字阴影削弱识读。

### 2.2 适用选择器

- `.hero-actions > a.primary`
- `.hero-actions > button.primary`
- 深色首屏／深色模块操作区内的 `.primary`
- 明确标记为 `.qily-hero-primary` 的链接或按钮

### 2.3 禁止事项

- 禁止只在项目合作页增加局部颜色补丁，而遗漏行业资源入驻及后续同类页面。
- 禁止用白色、浅金或半透明文字叠加浅金按钮底色。
- 禁止通过删除背景色、降低按钮透明度或缩小字号掩盖对比问题。
- 禁止公共“深色区域普通链接”规则覆盖主按钮语义。

## 3. 背景音乐连续性规则

### 3.1 全站覆盖

- 凡加载QilyLean公共导航壳的公开页面，必须加载统一背景音乐运行时。
- 首页、QilyLean AI、能力画像、履历主线、改善经验、知识分享、行走印记、友情链接、行业资源入驻和项目合作不得例外。
- 友情链接页面必须与其他模块具有相同的音乐按钮、静音状态和播放位置恢复能力。

### 3.2 运行时

- 全站只能存在一个音频元素和一个音乐控制按钮，禁止旧版与新版重复播放。
- 音频文件须在 `<head>` 中通过 `preload as="audio"` 提前请求。
- 音乐运行时使用单文件加载，不再采用页尾加载器二次加载核心脚本。
- 离开页面前写入当前播放位置、静音状态、播放状态和保存时间。
- 新页面取得音频元数据后，立即设置保存位置并执行播放，不得再等待 `seeked` 后才播放。
- 页面切换时间补偿须设置上限，避免因加载耗时把恢复位置大幅跳到未缓存区段。
- 自动播放被浏览器策略阻止时，应在用户首次触摸、点击或键盘操作后恢复；不得伪造已播放状态。

### 3.3 体验验收

- 从任一主模块跳转至友情链接，音乐按钮必须存在，音乐状态不得重置。
- 从友情链接跳转至其他模块，音乐播放位置须连续恢复，不得从0秒重新开始。
- 同源模块跳转不得出现旧版人为等待 `seeked` 导致的明显长停顿。
- 静音状态、按钮拖动、键盘焦点、移动端触摸和页面前后台切换均须正常。
- 受浏览器整页导航和自动播放策略限制，验收口径为“消除可避免的脚本等待、提前缓存、快速续播”，不得虚假承诺物理意义上的零毫秒无缝播放。

## 4. 发布与防回退

- 公共主按钮对比样式、音频预加载和V5音乐脚本必须由统一发布脚本注入全部公开HTML。
- 发布脚本必须删除旧 `homepage-music.js` 引用，避免两套音乐运行时并存。
- 生成脚本须可重复执行，第二次执行不得继续产生差异。
- CI必须验证：
  1. 项目合作与行业资源入驻两个主按钮文案仍存在；
  2. 公共样式同时包含 `color` 与 `-webkit-text-fill-color` 深色文字规则；
  3. 友情链接页面已加载V5音乐脚本及音频预加载；
  4. 全部公共导航页面无旧音乐脚本残留；
  5. 关键页面加载的公共样式位于 `</head>` 前；
  6. 发布脚本重复运行结果一致。
- 其他静态生成、导航发布、视觉物化或页面重建工作流完成后，须再次执行本规范发布器，防止缺页和旧缓存回退。

## 5. 公网复核

- PR、CI和主分支静态提交完成后，仍须分别在桌面Chrome／Safari及移动端Safari／Chrome复核。
- 复核页面至少包括：项目合作、友情链接、行业资源入驻和任一其他主模块。
- 公网未完成最终复核前，只能表述为“代码与静态物化已完成，公网效果待确认”，不得把PR合并等同于最终验收。

## 6. 纠偏记录

- 本次问题不是缺少页面内颜色声明，而是公共样式优先级、WebKit文字填充色和缓存加载顺序共同造成的覆盖。
- 本次音乐问题不是用户设备设置，而是友情链接漏装音乐脚本及旧版恢复流程存在可避免等待。
- 后续遇到相同问题，必须先检查公共选择器、生成源、缓存版本和全站注入，不得等待用户反复截图后再做单页补丁。

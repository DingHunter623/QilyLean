# QilyLean 全站运维总则｜稳定维护模式

生效日期：2026-08-24
适用范围：QilyLean 官网、Times26001、QilyLean Home、启力精益斗地主及其公开下载页、法律页、支持页、发布脚本、CI/构建流程与关联数字资产。

## 1. 总优先级：全站可视化效果第一位

QilyLean 的页面与数字产品运维，首先保证用户实际看到的视觉效果与品牌一致性，包括但不限于：

- 图片、图标、Logo、主视觉完整且清晰；
- 桌面端、平板端、移动端布局稳定，无错位、遮挡、异常换行及横向溢出；
- 标题、正文、按钮、卡片、留白、对齐、层级、对比度及交互状态遵循现行 VI；
- 重要图片和图文概述不得因所谓“性能优化”“代码精简”“结构统一”而被删除、降级或用临时示意图替代；
- 性能优化应优先采用压缩、WebP/AVIF、合理尺寸、缓存、预加载/懒加载等技术手段，不以牺牲可视化完整性为代价。

## 2. 必备前提：内容、技术含量与逻辑必须完整

“可视化效果第一位”不等于只看外观。以下属于发布前的必备前提：

1. 内容完整、事实口径正确；
2. 信息技术含量与工程专业度不得无故删减；
3. 页面、APP、下载、版本、链接、业务流程及数据逻辑正确；
4. 已存在且有效的图片、概述、功能、证据、下载入口和说明不得因局部整改被顺手删除；
5. 修改一个模块时必须评估相邻模块、公共组件、生成源和发布流程的回归风险。

任何整改若在“更简洁”与“信息完整”之间发生冲突，优先保留信息完整，再通过视觉层级解决信息密度问题。

## 3. 联系信息固定字段规范

正式对外联系字段统一使用：

- **官方网址**：`https://qilylean.com`
- **官网邮箱**：`admin@qilylean.com`

正式字段不得自行改写为“官网地址”“网站地址”“企业邮箱”“官方邮箱”“联系邮箱”等近义标签。

### 语境例外：禁止机械全局替换

“官网”作为正常业务语义时允许并应自然保留，例如：

- 官网首页
- 进入官网
- 官网导航
- 官网安装包
- 官网发布页
- 官网建设
- 官网内容
- 官网当前版本

“企业域名邮箱”等用于解释邮箱属性的普通正文也可保留。

因此，统一规范针对的是**正式字段标签与固定口径**，不是对“官网”二字进行机械全局替换。

## 4. SSOT 与生成源优先

发现线上或 APP 出现错误时，必须优先追溯真正的单一事实源（SSOT）：

1. 源码 / 数据源；
2. 公共组件；
3. 生成脚本；
4. CI / 构建与发布流程；
5. 最终静态页 / APK / AAB / 发布产物。

不得只修改最终生成文件而保留错误源头，否则视为未闭环。

对已有自动化生成链，整改后须同步增加防回退检查，避免后续任务再次覆盖正确内容。

## 5. 稳定维护模式

截至 2026-08-24，QilyLean 建站主体规模及信息架构已基本稳定。后续默认采用“稳定维护模式”：

- 常规工作以定期发布简报、更新项目/知识内容、修复真实缺陷为主；
- 无明确业务价值或用户要求，不主动大规模改版、重构、搬移模块或重新设计既有成熟视觉；
- 小问题采用最小差异修改，避免牵连无关页面；
- 不因一次局部需求重新定义已经确认的全站规范；
- 不为追求技术整洁而改变用户已经确认的内容、视觉、Logo、术语或操作习惯；
- 全站整改只有在确有共性缺陷时才扩大范围，并且必须保留既有正确内容。

## 6. 发布前检查顺序

每次网站或 APP 运维按以下顺序验收：

1. **视觉**：图片/Logo/图标/布局/字号/对齐/留白/对比度/移动端；
2. **内容**：图文是否完整，概述、专业信息和证据是否被误删；
3. **术语**：正式字段是否遵循“官方网址 / 官网邮箱”等全站固定口径；
4. **逻辑**：导航、按钮、链接、下载、版本、功能、数据与业务流程；
5. **技术**：性能、缓存、SEO、可访问性、构建、CI及兼容性；
6. **回归**：相邻模块、公共组件、源脚本、生成产物和移动端再次核验。

## 7. 禁止事项

未经明确需求，不得：

- 擅自替换 QilyLean / APP 已确认 Logo、图标或主视觉；
- 删除或缩减已确认的重要图片、图文概述、技术内容或业务信息；
- 为统一术语而进行无语境判断的全局替换；
- 只改最终 HTML / APK 而不修正实际生成源；
- 在稳定维护阶段主动扩大整改范围、重复造轮子或重新设计成熟模块；
- 把内部验证、构建、签名、测试过程术语直接暴露成用户侧产品文案。

本总则作为后续 QilyLean 运维、自动化整改和代码审查的上位执行原则；若专项规范与本总则冲突，优先保证用户已确认的视觉、内容完整性和业务口径，再做技术实现调整。
